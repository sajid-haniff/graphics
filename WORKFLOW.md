# Demo Development Workflow

## Phase 1 — Design

Define:

- objective
- constraints
- learning goal
- acceptance criteria

Human owns architecture and design decisions.

## Phase 2 — Implementation

Codex:

- creates feature branch
- implements algorithm
- creates demo
- updates registry
- runs build
- summarizes changes

## Phase 3 — Review

Review:

- correctness
- architecture
- coding style
- performance implications
- educational value

## Phase 4 — Code Documentation

Codex adds:

- JSDoc
- implementation comments
- engineering rationale

Comments should explain why, not merely what.

## Phase 5 — Educational Documentation

Inputs:

- algorithm source
- demo source

Outputs:

- GitHub markdown
- mathematical explanation
- implementation mapping
- SVG diagrams
- complexity analysis
- engineering notes

Documentation standard:

Mathematics
    ↓
Algorithm
    ↓
Implementation
    ↓
Visualization

## Phase 6 — Merge

After successful review:

- merge feature branch into main
- delete feature branch

## Success Criteria

Every topic should ultimately contain:

- implementation
- demo
- source-level documentation
- educational documentation
- SVG visualizations
